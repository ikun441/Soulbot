# 本地日记 · v0.9.9

日记由真实成功活动的计数生成，按机器人、用户、群/私聊隔离保存。默认关闭采集，启用后默认在配置时区每天 00:30 处理前一天；默认仅保存本地。本版不调用模型润色，也没有发送、公开或 QQ 空间发布接口。

## 开始使用

1. 打开“本地日记”，启用并保存规则。从此之后的成功 QQ 交流才会留下计数活动，已有聊天不会回填。
2. 默认每个会话在一天内至少有 2 次活动才生成一篇，不能合并其它用户、群或私聊来凑数。
3. 每天到配置时间后自动生成前一天记录；也可以选择保留期内已结束的日期，点击“生成本地日记”。无活动或不足门槛时跳过。
4. 在列表查看详情，编辑标题及角色表达，下载本篇私人 JSON，或删除日记及其当日活动。

管理试聊、Provider 测试、管理命令、失败发送和沉默不计入这些活动。一次消息批次最终成功回复算一次交流，即使包含文字和多张媒体；文字及媒体计数可重叠。

## 事实与角色表达

事实层只保存成功活动类型、确认时间、所属会话和去重摘要，不保存聊天正文、媒体内容、昵称或模型输出。普通交流只有发送器确认成功后才记录；主动私聊只有任务进入“已确认发送”后才记录，未确认的在途任务不会当作已发生的经历。

每篇日记保存生成时的时区、日期边界和事实快照：总活动、成功交流、含文字/媒体的交流、主动消息确认次数及首末活动时间。编辑 API 不能修改这些事实字段。日期使用配置时区的自然日，处理夏令时的 23/25 小时日期。

角色表达初稿是带 AI 名称的本地模板。管理员可以编辑标题和表达，来源会标记为手动编辑；它是角色化叙述，不代表 AI 的真实主观感受，也不能作为事实证据。可选的 LLM 润色和更丰富的真实事件类型留待后续版本。

## 用户隐私控制

QQ 命令作用于当前机器人、当前用户以及当前群或私聊：

- `/日记 关闭`：停止该会话的活动采集和新日记生成，已有记录保留。
- `/日记 开启`：恢复本会话许可，仍需管理员启用全局功能。
- `/删除日记`：删除该会话全部日记和活动，并暂停后续采集；其它会话分别管理。

群聊需 @机器人或明确回复机器人。语音转写不执行这些控制命令。隐私关闭/删除优先保存，即使普通聊天停用或处于回复冷却；确认消息仍受回复权限与频率限制。

所有查看、编辑、导出和删除接口都要求管理员登录，写操作同时校验来源。导出含私人会话标识，需自行妥善保存。普通配置导出和审计日志不包含日记内容；日记不会自动进入其它会话的 Prompt、长期记忆、主动消息或公开草稿。

## 调度、保留与删除

自动任务每分钟检查一次，处理前一自然日，完成状态持久保存。重启不会重复生成，已有日记及手动表达不会被覆盖。停机多日后只自动处理最近结束的一天，更早日期可在活动保留期内手动生成。修改时区不改写已有日记；同一会话和日期只有一篇，详情保留原生成时区。

活动默认保留 90 天，可设置 7–365 天。到期清理原始活动，已生成快照保留至删除。删除单篇会同时删除其会话在该日记所用日期边界内的活动，防止直接重新生成；用户 `/删除日记` 还会关闭该会话未来采集。

日记生成与编辑/删除使用 SQLite 事务和修订号，冲突返回 409，刷新核对后保存。活动采用持久去重摘要，重放同一事件不会重复计数；消息发送成功到可选日记记录之间若异常，可能少记活动，系统不会补编经历，也不因此重复发送 QQ 消息。

## 配置与升级

`diary` 使用与 WebUI 相同的 Pydantic Schema：enabled、auto_generate、generation_time、min_events、fact_retention_days，均可热更新。旧的 `behavior.diary` 保持 false，请使用新的独立配置。

升级前停止服务并备份 config.yaml、.env、data。schema v10→v11 追加活动、偏好、日记和生成状态表，保留账号、记忆、情绪、关系及主动联系队列。回退需恢复兼容数据库备份。

专项验证：`.venv/bin/python -m pytest -q tests/test_diary.py`。浏览器验收使用隔离实例和明确的本地活动夹具，验证真实管理 API；实际 QQ 活动采集仍需正确接入 NapCat 后交互验收。

## v2.0.0：当天预览与空间活动

`diary.live_preview` 默认 true。启用日记且达到 min_events 后，打开日记页或后台每分钟会生成/刷新当天进行中记录；页面每 10 秒刷新列表，不覆盖正在编辑的表达。可以手动生成今天，API 传 include_current_day=true。已完成日期按时区归档；事实变化保留人工标题/表达，自动模板随事实更新。

只有 qzone_drafts 中带有效平台回执的 published 动态被计为 qzone_posts，独立为机器人空间活动，不冒充私聊或复制正文。导入仅保存类型/计数/时间；不确定结果不计入。diary_qzone_seen 保持去重和删除后的导入标记，删除日记不会自动重建。默认关闭日记时不采集或导入。

本次按用户要求为独立测试实例启用日记、实时预览，并把事件门槛设为 1，让刚完成的真实空间活动立即显示；新安装默认门槛仍为 2，可在 WebUI 调整。无足够事件则提示原因，不编造经历。SQLite 升级 schema v13，保留旧事实和既有日记，旧日记标记为已归档。
