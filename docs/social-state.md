# 好感度与全局模拟情绪 · v0.9.5

这两项功能是可编辑的角色参数。它们不是 AI 真实主观感受的测量，不改变权限、预算、免打扰或用户拒绝。首次升级自动创建 schema v8 表，不把已有聊天补算成好感度。

## 全局情绪

WebUI 的“全局情绪”页面显示愉悦度、活跃度、好奇心、社交意愿和疲劳度，均为 0–100。可以保存当前数值、恢复已保存基线、关闭功能或冻结自动演化。修改基线仅修改恢复目标；点击“恢复基线数值”才会立即替换当前值。

默认基线依次为 60、55、60、50、10。自动演化按 180 分钟半衰期靠近基线；关闭/冻结期间不积累待恢复时间。规则改变后的首次读取从新规则应用时刻重新计时，不追溯模拟。时钟回拨不产生额外增长或负时间恢复。程序无需为情绪额外请求 LLM。

| 状态 | 默认进入条件 | 默认退出缓冲 |
| --- | --- | --- |
| 疲惫 | 疲劳 ≥75，或活跃 ≤25 | 疲劳 ≤65 且活跃 ≥35 |
| 低落 | 愉悦或社交意愿 ≤25 | 愉悦及社交意愿均 ≥35 |
| 活跃 | 活跃 ≥75 且愉悦 ≥65 | 活跃 ≤65 或愉悦 ≤55 |
| 好奇 | 好奇 ≥75 | 好奇 ≤65 |
| 愉快 | 愉悦 ≥75 | 愉悦 ≤65 |
| 平静 | 无更高优先状态 | 按上方顺序重新判断 |

按表格顺序选择优先状态，自动转换默认至少停留 60 秒，手动编辑立即重判。高/低阈值、滞回宽度和最短停留可在高级规则中调整；阈值区间冲突会拒绝保存。

成功完成直接或连续会话回复后，每个全局冷却窗口最多更新一次：愉悦 +0.5、活跃 -0.5、好奇 +0.3、社交意愿 +0.4、疲劳 +1，限制在 0–100。默认冷却 60 秒。不按消息词语判断正负情感，不保存消息正文。最近 512 次数值更新/转换持久保留，管理端展示最近 40 次趋势。时间恢复按访问时计算，无需后台循环或云端调用。

## 好感度与关系

“好感与关系”页面可以按用户 QQ、群号或称呼查询，并新增、编辑、冻结或删除关系。关系键是机器人 QQ、群号（私聊为空）、用户 QQ；这些标识创建后不能直接改换范围。需要其它会话时新建记录。

好感度为整数 -100–100，默认 0。显示“谨慎相处 / 初识 / 认识 / 熟悉 / 亲近”等表达标签，分别对应低于 -40、低于 10、低于 40、低于 70、其余分数。管理员可以直接调整称呼与分数。关闭单条自动记录后，保留手动设置并停止这条记录的自动计数和增长。

自动积累只依据真实成功的直接/连续互动：默认每 300 秒最多 +1，每条关系每个统计日最多 +5；统计日使用系统配置时区。消息重复、发送失败、沉默、主动插话和 WebUI 试聊不奖励。多个用户并发时使用 SQLite 事务保持限额。重启、手动编辑分数和冻结/恢复都不清零当天已用额度。

删除会清除这条关系，下次成功互动可能重新建立。如仅希望停止记录，关闭该条自动记录即可。管理员删除属于显式数据清理，重新建立的记录从默认值开始。

## 编辑、隔离与回复

所有编辑 API 要求管理员会话及写请求头，修订号不匹配返回 409；先刷新并核对新状态，再保存，避免覆盖刚发生的互动。无效数值、非有限浮点、非法 QQ 标识和未知字段会被拒绝。关系称呼和数值不会写入普通配置导出或审计详情。

QQ Prompt 只读取当前机器人、群/私聊及用户的关系，全局情绪只包含无来源身份的数值与标签；不同群和私聊的称呼不会互相加入 Prompt。WebUI 试聊读取全局情绪，不加载 QQ 个人关系，也不增加好感。模型没有直接修改情绪或好感的工具。

本版交付的是 M3 的关系与情绪基础，长期记忆提取/检索、日记和自主社交仍在后续版本。升级前停止服务并备份 config.yaml、data/ 和 .env；schema v8 数据不能直接交给不支持它的旧版程序。

开发验证：`.venv/bin/python -m pytest -q tests/test_social_state.py` 覆盖状态机、时间恢复、事务、隔离、持久限额与 Agent 集成；`node --test tests/web/page-session.test.mjs` 验证页面请求竞态，不需要额外前端依赖。浏览器验收使用独立本地实例与测试账户，不代表真实 QQ/云端 Provider 已验收。
