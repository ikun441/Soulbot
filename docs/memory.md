# 长期记忆 · v0.9.7

本版提供 SQLite 候选记忆、管理员审核、会话隔离检索和个人控制。普通聊天仍只进入限时短期上下文，不会逐条永久保存。初版候选来自用户明确的 `/记住 内容` 或管理员整理；尚未实现额外 LLM 语义提取、向量检索或跨会话共享，不追加提取模型费用。

## 使用

1. 在 WebUI 的“长期记忆”启用功能并保存规则，默认关闭。
2. 用户私聊发送 `/记住 我喜欢轻音乐`；群聊需 @机器人再发送此命令。系统按原消息过滤和冷却处理，生成候选并保留来源消息 ID。
3. 管理员在记忆页核对内容、机器人 QQ、用户 QQ、群号、来源、重要性及可信度。编辑候选，确认已获准长期保存，将审核结果改成“已通过”并保存。
4. 下一次相同会话的 QQ 回复才会检索此条。使用“预览此会话可用记忆”可检查同一检索结果，不调用模型或发送 QQ 消息。

手动新增也先保存为候选，无法在创建请求中直接通过。状态包括待审核、已通过、已拒绝和已归档；修改时使用修订号，冲突返回 409，刷新核对后再保存。机器人、用户和群号创建后不可修改，需要更改范围时重新建立并审核。

## 用户控制

- `/记忆 关闭`：停止本会话的候选采集和检索，保留已有条目。
- `/记忆 开启`：恢复本会话开关，仍受全局开关和审核约束。
- `/忘记我`：删除当前机器人、当前群或私聊、当前用户的长期记忆和候选。其它会话分别删除。

命令不调用 LLM；语音转写不会执行这些存储命令。群黑名单、关闭接入、静默、临时禁言及回复冷却仍生效。命令确认发送失败时可能已保存/删除，请从 WebUI 核对。

个人开关在 SQLite 持久化，重启不会重置。关闭功能不撤回已经发给模型的在途上下文；删除长期记忆也不会清理既有短期上下文、服务商已处理数据或 QQ 历史消息。短期上下文可在“聊天与权限”单独清理，并按配置自动过期。

## 范围、检索和预算

每条记忆包含 ID、正文、分类、来源、创建/更新时间、所属机器人/人物/会话、可见范围、重要性 1–5、可信度 0–1、长期保存许可、审核状态、有效期及修订号。六种分类为对话、人物、事件、关系、自我和日记；分类只是整理标签，不会生成日记或扩大可见范围。

私聊只查同一机器人与用户；群聊还必须匹配同一群和同一用户。没有全局公开或跨群共享入口。管理试聊不读取 QQ 记忆。管理端读取接口需要登录，写接口同时校验来源；普通配置导出和审计日志不包含记忆正文。

候选按 Unicode 规范化、大小写和空白归一去重，只合并同一会话的完全相同内容，不做语义合并。重复提交不会修改已有条目的授权、状态、来源或有效期。每个会话最多同时有 50 条待审核候选，防止无限累积。

检索首先用 SQL 限定会话、已通过、获准保存、未过期，再在重要性/可信度优先的最多 200 条候选中按中文双字或英文关键词相关性排序。默认最多返回 4 条、结构化 JSON 不超过 1200 字符；范围在相同 Pydantic 配置 Schema 中可编辑。超长条目整条跳过，仍由 LLM 服务执行总 Token 和费用预留。记忆作为引用数据进入 Prompt，不能自行执行指令、修改配置或授予工具权限。

新候选留空有效期时默认 30 天；审核通过时清空有效期表示长期有效。到期的候选/已通过条目在读取时自动归档，不再检索；归档不等于删除。管理员可以拒绝、归档或删除条目。已过期条目需先修改有效期才能再次通过。

## 升级与验证

升级前停止服务并备份 `config.yaml`、`.env`、`data/`。SQLite 自动从 schema v8 追加迁移到 v9，保留既有账号、关系、情绪、上下文和用量。回退旧程序时须恢复兼容的数据库备份。

专项测试：`.venv/bin/python -m pytest -q tests/test_memory.py`，覆盖审核授权、作用域隐私、并发去重、到期、修订冲突、个人控制、API 和真实 Agent 集成；隔离浏览器验收不等于真实 QQ 新命令已完成用户交互验收。
